# Timepin: сводка проекта

Сводка соответствует `docs/decisions.md`. Подробности — в журнале решений.

## Тема ВКР

«Проектирование и разработка программного комплекса для асинхронного рецензирования видеоматериалов с привязкой к таймкоду».

## Проблема

Монтажёры согласовывают правки с заказчиками и коллегами в мессенджерах и почте. Замечания теряются в переписке, место правки описывается неточно («где-то на второй минуте»), непонятно, какие правки уже выполнены. На каждый раунд уходит лишнее время.

## Идея решения

Программный комплекс из двух частей на одном React-коде (D-013):

- **Desktop-приложение (Electron)** для монтажёра: создаёт проект, загружает версии видео в раунды, управляет комментариями и статусами, выпускает новый раунд;
- **Веб-клиент** для гостей и рецензентов: открывает версию по ссылке, ставит комментарии на конкретный момент, рисует на кадре.

Комментарии имеют статус (открыт / выполнен / отклонён). Открытые замечания переносятся в новый раунд (D-006).

## Целевая аудитория

- **Основная:** фрилансер-монтажёры и видеографы, которые монтируют сами и работают с заказчиками напрямую (свадебное и семейное видео, корпоративные ролики, реклама, блоги).
- **Вторичная:** заказчики, которые оставляют рецензии. Они работают в браузере по ссылке, без установки программы. Регистрация для них добровольная (D-014).
- **Не целевая на MVP:** студийные монтажёры и кинопроизводство.

## Ключевые решения

Подробнее в `docs/decisions.md`.

- **Платформа:** desktop (Electron) для монтажёра и веб-клиент для гостей и рецензентов, общий UI в `packages/ui` (D-013). Desktop поддерживает macOS и Windows (D-021).
- **Гостевой доступ:** ссылка с выбираемым сроком действия, вход только по имени. Регистрация дает доступ к проектам, управление комментариями и email-уведомления (D-014).
- **Аккаунты:** для создания проектов нужен аккаунт. Данные проектов хранятся на сервере, браузер и desktop их не хранят (D-016).
- **Точность:** комментарий привязан к номеру кадра в постоянной сетке прокси, отображается как ЧЧ:ММ:СС:КК (D-022).
- **Видео:** до 10 минут. Прокси H.264 создаётся на машине монтажёра через FFmpeg, на сервер загружается только прокси (D-005).
- **Структура данных:** проект, раунд, версия, комментарий, рисунок, статус. Комментарии могут быть без привязки к моменту, это заменяет общий чат (D-006).
- **Вне MVP:** общий чат, браузерный редактор проектов, соавторы, интеграции с Premiere и Resolve, оплата, офлайн-режим, мобильные клиенты (D-015).

## Стек

- **Frontend:** React 19, TypeScript, Vite, electron-vite. Плеер на чистом TypeScript поверх `<video>` и canvas.
- **Backend:** Python, FastAPI, SQLAlchemy 2.0, Alembic, PyJWT, bcrypt.
- **БД и файлы:** SQLite в MVP, файлы на диске сервера (D-009). Переход на PostgreSQL и S3-хранилище возможен позже.
- **Инфраструктура:** монорепозиторий (`apps/desktop`, `apps/web`, `apps/server`, `packages/ui`, `packages/api-client`), Docker Compose, деплой на российский VPS (последний этап разработки) (D-010).
- **Отказались:** Firebase и Supabase (нестабильный доступ из РФ, проблемы с оплатой). Svelte (выбран React по опыту автора и поддержке нейросетей).

## Процесс

Проектирование по стадиям и этапам ГОСТ Р 59793-2021 (см. `docs/01-process.md`, D-012). Код пишется на этапе 6.2, после утверждённого технического проекта.

- **Стадия 1. Формирование требований.** Обследование (интервью, опрос на Anketolog, сравнение аналогов: Frame.io, Wipster, Filestage, Vimeo Review, Ziflow), требования пользователя, отчёт. Текущая стадия. Границы MVP зафиксированы (D-015), метрики не определены (D-017).
- **Стадия 2. Концепция.** Изучение объекта, технические проверки, выбор варианта концепции, оценка рисков проекта, отчёт.
- **Стадия 3. Техническое задание** по ГОСТ 34.602-2020.
- **Стадия 4. Эскизный проект.** Минимальный объём.
- **Стадия 5. Технический проект.** Архитектура, данные, API, роли.
- **Стадия 6. Рабочая документация и разработка.**
- **Стадия 7. Ввод в действие.** Испытания, опытная эксплуатация, приёмка.
- **Стадия 8. Сопровождение.** Описывается, не выполняется.

# S2. Плеер: точность по времени

Одноразовая проверка, код не переносится в продукт. Результаты и выводы — в `docs/04-spikes.md`, раздел S2.

Требуется: FFmpeg с `drawtext` (необязательно, номер читается и по блокам) и Node.js. Любой современный браузер.

| Файл | Что делает |
|---|---|
| `gen-test-videos.sh` | Создаёт тестовые видео в `out/` (по 2 минуты, 720p): в каждый кадр зашит номер двоичным кодом (16 блоков в левом верхнем углу). Рядом `<имя>.truth.json` с временем показа и ключевыми кадрами. Выбор вариантов: `ONLY=cfr30-g30,vfrfilled30-g30 ./gen-test-videos.sh` |
| `serve.mjs` | Сервер на `127.0.0.1:8765`: страница теста, видео с поддержкой диапазонов байт, приём результатов в `out/results-*.json` |
| `make-real-test.sh`, `real-truth.mjs` | Реальные ролики iPhone из `../s1-ffmpeg-proxy/media/`: зашивает номер кадра, делает прокси `iphone6s-vfr/cfr`, `iphone13-vfr/cfr`, читает истину с картинки и печатает сдвиг содержимого |
| `index.html` | Тест: перемотка на 123 момента, шаг на кадр тремя способами, воспроизведение 4 с; номер кадра читается с картинки |

Варианты видео:

| Имя | Что проверяет |
|---|---|
| `cfr30-g1`, `cfr30-g30`, `cfr30-g250` | Постоянные 30 к/с; ключевой кадр на каждом кадре, раз в секунду, раз в 8,3 с |
| `ntsc2997-g30` | Дробная частота 30000/1001 |
| `vfr30-g30` | Сильно переменная частота (выбрасывается треть кадров) |
| `vfrmild30-g30` | Слабая переменная частота (каждый 60-й кадр), как у iPhone |
| `vfrfilled30-g30` | Те же пропуски, заполненные повтором кадра: постоянная частота |
| `cfr60-g60`, `pal25-g25`, `film23976-g24` | Частоты 60, 25 и 23,976 к/с |

Запуск:

```bash
./gen-test-videos.sh          # около 40 с; если падает drawtext: NO_TEXT=1 ./gen-test-videos.sh
node serve.mjs                # оставить работать
# открыть в браузере: http://127.0.0.1:8765/?auto=1   (все варианты, около 3 минут)
# или http://127.0.0.1:8765/   и выбрать вариант вручную
```

Сравнение способов хранить момент комментария (миллисекунды и номер кадра), шаг на кадр и сохранение при паузе: `http://127.0.0.1:8765/?mode=frames&auto=1` (около 10 минут на все видео).

Страница показывает таблицу и сохраняет JSON с результатами и строкой браузера в `out/`. В таблице «точно» — число перемоток, после которых показан именно ожидаемый кадр; «шаг» — успешные шаги на кадр из 30 тремя способами.

## Автоматический прогон по браузерам

`node run-browser-matrix.mjs` сам находит установленные браузеры (Chrome, Edge, Firefox, Safari), открывает страницу теста с чистым профилем, ждёт результат, закрывает браузер и печатает сводку (`out/summary.md`). Параметры: `--browsers chrome,edge,firefox,safari`, `--mode frames|main|both`, `--variants ...`, `--timeout-min N`. Режим `--mode pausealign` — сквозной тест паузы (пауза, номер кадра из `mediaTime`, выравнивание, сдвиг в кадрах). Окна браузера не сворачивать: скрытая страница не получает обратных вызовов кадров. Сводка по всем накопленным результатам: `node summarize-results.mjs`.

Полный прогон на новой ОС одной командой: `../run-windows-checks.sh`, инструкция для Claude Code: `../RUNBOOK-WINDOWS.md`.

## Прогон на новой ОС или в новом браузере вручную (чек-лист)

Исходные данные: репозиторий получен (`git pull`), в `../s1-ffmpeg-proxy/media/` лежат оба ролика iPhone (имена в корневом `README.md`).

1. `./gen-test-videos.sh` (около минуты; при ошибке `drawtext`: `NO_TEXT=1 ./gen-test-videos.sh`).
2. `./make-real-test.sh` (нужны ролики iPhone и FFmpeg с `zscale`; несколько минут, HDR-ролик самый медленный).
3. `node serve.mjs` (оставить работать).
4. В браузере открыть (всё в одну строку):

   `http://127.0.0.1:8765/?mode=frames&auto=cfr30-g30,cfr30-g250,cfr60-g60,ntsc2997-g30,iphone6s-cfr,iphone13-cfr,vfrmild30-g30,vfr30-g30`

   Вверху страницы появится «готово» (около 12–15 минут). Дополнительно, если есть время: `http://127.0.0.1:8765/?auto=1` (задержка перемотки и шаг на кадр, около 5 минут).
5. Результаты сохранены в `out/results-*.json` (строка браузера внутри). Таблицу занести в `docs/04-spikes.md`, раздел S2 (колонка «Движок»), странности — в журнал находок.
6. Если в браузере нет `requestVideoFrameCallback`, страница это отметит (`requestVideoFrameCallback: false`), тест паузы пропустится; это тоже результат.

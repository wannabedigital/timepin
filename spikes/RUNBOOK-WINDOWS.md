# Инструкция для Claude Code на Windows: прогон проверок S1 и S2

Этот файл — задание для Claude Code, запущенного на Windows-машине автора. Выполняй шаги по порядку, **без вопросов автору**, пока не упрёшься в блокировку, которую нельзя обойти (см. раздел 5). Автор просил, чтобы прогон прошёл без его участия.

## 0. Что нужно получить и зачем

Проект Timepin: прокси видео создаётся FFmpeg на машине монтажёра (D-005), комментарий привязывается к номеру кадра (D-022). На macOS всё проверено (Chromium и Safari). На Windows нужно:

- **S1:** перемерить перевод HDR в SDR с новым порядком фильтров (раньше 113,6 с на этой машине; на macOS после исправления 12,7 с против 27,4 с).
- **S2:** проверить точность перемотки и привязки к кадру в Chrome, Edge и Firefox на Windows. Главный вопрос: в каждом ли браузере «середина кадра» даёт 123 из 123 на видео с постоянной частотой, как в Chromium и Safari на macOS; как ведёт себя переменная частота; есть ли `requestVideoFrameCallback`.

Не принимай новых проектных решений. Результаты записываются в документы, а не меняют D-022 (правила в разделе 4).

## 1. Правила

- Прочитай `CLAUDE.md` и разделы S1 и S2 в `docs/04-spikes.md` до начала.
- Работай в Git Bash (`C:\Program Files\Git\bin\bash.exe`) или из Bash-инструмента, если он уже Git Bash. Скрипты `.sh` не запускаются в PowerShell и cmd.
- Тестовые видео и `out/` в git не попадают. Не добавляй их в индекс, не трогай `media/` (исходные ролики не менять).
- Коммит локально разрешён этим заданием (одним коммитом, раздел 6). **Push не делай**, если автор в этой сессии явно не попросил.
- Скрипты не модифицируй, если нет блокировки. Если пришлось исправить скрипт, опиши исправление в журнале находок.
- Долгие команды запускай в фоне и опрашивай лог: прогон занимает около 1–1,5 часа.

## 2. Предусловия (проверить и при необходимости исправить)

```bash
git pull                      # получить последние скрипты и документы
git log --oneline -3
uname -s                      # ожидается MINGW64_NT-...
node -v && ffmpeg -version | head -1 && ffprobe -version | head -1
ls spikes/s1-ffmpeg-proxy/media/real-*.mp4 spikes/s1-ffmpeg-proxy/media/real-*.mov
```

Требования:

- Видео в `spikes/s1-ffmpeg-proxy/media/`: `real-bbb-1080p30-10min.mp4`, `real-iphone13pro-4k-dv-hlg-60.mov`, `real-iphone6s-4k-h264-2997.mov`. Если нет, остановись и сообщи автору (имена и источники — в корневом `README.md`).
- FFmpeg должен быть полной сборкой с `zscale`, `drawtext`, `libvmaf`, `libx264`. Проверка: `node spikes/s1-ffmpeg-proxy/env-check.mjs`. Если установлен shim или сборка без `zscale`, используй `FFMPEG_FULL=<полный путь к ffmpeg.exe>` для скриптов, где он поддерживается (`hdr-compare.sh`, `gen-test-videos.sh`).
- В скриптах не должно быть `\r`. Если видишь ошибки вида `$'\r': command not found`: `git config core.autocrlf false && git rm --cached -r -q . && git reset --hard` (рабочие файлы без изменений не потеряются: перед этим убедись, что `git status` чист).
- Браузеры: хотя бы один из Chrome, Edge, Firefox. Сценарий сам найдёт установленные.

## 3. Прогон

Одна команда из корня репозитория, в фоне:

```bash
nohup ./spikes/run-windows-checks.sh > spikes/run-windows-checks.out 2>&1 &
```

Следи за ходом:

```bash
tail -n 30 spikes/run-windows-checks.out
cat spikes/_run-logs/status.txt
```

Ожидаемые этапы и время (ориентиры):

| Этап | Что делает | Время |
|---|---|---|
| env-check | версии и возможности FFmpeg | секунды |
| hdr-compare | перевод HDR пятью способами, время и качество | 5–10 мин |
| gen-test-videos | тестовые видео с номерами кадров | 1–3 мин |
| make-real-test | видео из роликов iPhone с номерами кадров | 5–10 мин |
| browser-matrix | `?mode=frames` в Chrome, Edge, Firefox по очереди (окна открываются и закрываются сами) | 12–20 мин на браузер |
| browser-main | основной тест (задержка, шаг) | 4–8 мин на браузер |

Пока идёт `browser-matrix`, не запускай других тяжёлых задач и не трогай открытые окна браузеров: они управляются сценарием.

Если сценарий завершился с ненулевым кодом, прочитай `spikes/_run-logs/*.log` для упавшего шага и действуй по таблице раздела 5. Затем можно перезапустить только упавший шаг вручную (команда указана в `run-windows-checks.sh`).

Результаты:

- `spikes/s1-ffmpeg-proxy/out/hdr/` и `spikes/_run-logs/hdr-compare.log`: время и качество каждого варианта перевода HDR;
- `spikes/s2-player-seek/out/results-*.json`: сырые результаты, строка браузера внутри;
- `spikes/s2-player-seek/out/summary-all.md`: сводные таблицы по браузерам.

## 5. Если что-то пошло не так

| Симптом | Действие |
|---|---|
| `$'\r'` в ошибках bash | см. раздел 2, исправление переводов строк |
| `gen-test-videos.sh` падает на `drawtext` | скрипт сам повторит с `NO_TEXT=1`; если упало и это — приложи текст ошибки в журнал и продолжай с имеющимися видео |
| `make-real-test.sh`: «Нет фильтра zscale» или похожее | FFmpeg без `zscale`: поставить полную сборку (`choco install ffmpeg-full` или gyan.dev) или указать `FFMPEG_FULL`; если нельзя, пропустить `iphone13-*`, прогнать только `iphone6s-*`, указать причину |
| `make-real-test.sh` слишком долго | это HDR-ролик (перевод цвета); дождись, сценарий ждёт сам |
| Браузер не найден | сценарий пропускает его; в отчёте перечисли, какие браузеры реально прошли |
| Браузер запустился, результата нет за таймаут | в логах `browser-matrix.log` будет строка о таймауте; повтори один раз для этого браузера: `cd spikes/s2-player-seek && node run-browser-matrix.mjs --browsers firefox --mode frames`; если снова нет, зафиксируй как находку |
| Порт 8765 занят | найди и останови старый `node serve.mjs`; повтори |
| Firefox: нет `requestVideoFrameCallback` | это результат, не ошибка: тест паузы пропустится, запиши в журнал |
| Что-то требует решения автора (например, нужно ставить ПО, а прав нет) | остановись, опиши в итоговом отчёте, что именно нужно |
